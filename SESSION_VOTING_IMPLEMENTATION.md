# Per-Session Voting Implementation

## Overview

The Arena system now supports **per-user/session voting**, allowing multiple independent users (each with their own session) to vote on the same comparisons without interfering with each other's voting status.

## Architecture

### Session Management

Each client gets a unique **session ID** (UUID) that:
- Is generated by the client via `X-Session-ID` header or via `/arena/session` endpoint
- Is stored in browser localStorage (`arena_session_id`) for persistence across page reloads
- Identifies a unique voter/user for tracking purposes

### API Endpoints

#### `GET /arena/session`
Generates and returns a new session ID (optional - clients can generate their own UUIDs).

**Response:**
```json
{
  "session_id": "95cf6919-4e13-48a0-848d-a143fcb1b393"
}
```

#### `POST /arena/vote`
Submits a vote with required `X-Session-ID` header.

**Headers:**
- `X-Session-ID`: Session identifier (required)

**Body:**
```json
{
  "comparison_id": "112f4820-7180-47c5-87d8-15a10f40002f",
  "vote": "A",
  "subset_id": 1,
  "comment": "Optional comment"
}
```

**Response:**
```json
{
  "success": true,
  "message": "Vote 'A' recorded successfully"
}
```

#### `GET /arena/voted?session_id=<uuid>`
Returns all comparison IDs that a specific session has already voted on.

**Response:**
```json
{
  "comparison_ids": [
    "112f4820-7180-47c5-87d8-15a10f40002f",
    "...more ids..."
  ]
}
```

#### `GET /arena/statistics`
Returns aggregated statistics based on per-session voting (keeps the latest vote per session+comparison).

**Response:**
```json
{
  "distinct_user_votes": 4,
  "votes_for_a": 2,
  "votes_for_b": 2,
  "votes_tie": 0,
  "votes_both_bad": 0,
  "win_rate_a": 0.5,
  "win_rate_b": 0.5,
  "tie_rate": 0,
  "both_bad_rate": 0
}
```

## Data Storage

### Primary: `arena_user_votes.jsonl`
Append-only log of all votes, one JSON object per line.

**Structure:**
```json
{
  "comparison_id": "uuid",
  "vote": "A|B|tie|both_bad",
  "comment": "optional string or null",
  "subset_id": 1|2|3|4,
  "session_id": "uuid",
  "timestamp": "2026-01-14T14:21:47.852769"
}
```

### Secondary: Global vote storage (backward compatibility)
The `default_storage.update_vote()` function still updates the global vote counter for backwards compatibility with existing analytics.

## Implementation Details

### How Voting Works

1. **Session Initialization**
   - Client generates or receives a session ID
   - Session ID is stored in browser localStorage
   - Persists across page reloads

2. **Checking Voted Status**
   - UI fetches `/arena/voted?session_id=<sid>` to get list of already-voted comparisons
   - UI filters out voted comparisons from the available list
   - Ensures users only see unvoted comparisons

3. **Submitting a Vote**
   - Client includes `X-Session-ID` header in POST request
   - Vote is logged to `arena_user_votes.jsonl` with session ID and timestamp
   - Global storage is also updated for backwards compatibility
   - Response confirms success

4. **Statistics Aggregation**
   - Reads all votes from `arena_user_votes.jsonl`
   - Groups by (session_id, comparison_id)
   - Keeps only the latest vote per pair (based on timestamp)
   - Aggregates counts: votes_for_a, votes_for_b, etc.
   - `distinct_user_votes` = number of unique (session_id, comparison_id) pairs

## Key Features

✅ **Multiple Independent Users**: Each session maintains its own voting status  
✅ **Same Comparison Voting**: Different users can vote on the same comparison with different votes  
✅ **Persistent Sessions**: Session ID saved in localStorage survives page reloads  
✅ **Append-Only Logging**: All votes tracked chronologically with timestamps  
✅ **Per-Session Stats**: Statistics aggregated by session for accurate user counts  
✅ **Backward Compatible**: Global vote storage still maintained  
✅ **No Session Server Storage**: Sessions are client-side; no server state needed  

## Testing

### Manual API Testing
```bash
# Get a session ID
SESSION=$(curl -s http://localhost:8001/arena/session | jq -r '.session_id')

# Check unvoted comparisons
curl -s "http://localhost:8001/arena/voted?session_id=$SESSION"

# Submit a vote
curl -X POST http://localhost:8001/arena/vote \
  -H "X-Session-ID: $SESSION" \
  -H "Content-Type: application/json" \
  -d '{"comparison_id": "...", "vote": "A"}'

# Check statistics
curl -s http://localhost:8001/arena/statistics
```

### UI Testing
1. Open http://localhost:8002/ in browser
2. Comparisons are automatically filtered to show only unvoted items
3. Submit votes via UI
4. Session ID is automatically managed and persisted in localStorage
5. Page reload preserves session and filters out previously voted comparisons

## Database Files

- **arena_votes.jsonl**: Global comparison votes (legacy, still maintained)
- **arena_user_votes.jsonl**: Per-session detailed vote log (new)

## Migration Notes

- Existing votes are still present in `arena_votes.jsonl`
- New votes are logged to both files
- Statistics endpoint uses `arena_user_votes.jsonl` for accurate per-session aggregation
- No data loss; both logs are maintained for analytics and auditing
